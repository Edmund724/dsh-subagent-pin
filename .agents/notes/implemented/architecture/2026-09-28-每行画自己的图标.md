# 每行画自己的图标

2026-09-28。Plugin Manager 里，组合包卡片与两条 insert 行各自画哪张图。

本文只留决策本身、逐项核实过的位置、与排除掉的选项；名字那一半见
`2026-09-28-每行显示自己的名字.md`，几何与配色的出处写在
`opencode-header.icon.svg` 的文件头。

## 结论

- `subagent-pin` 那行继续画包根的 `icon.svg`（图钉）——它就是本插件的标记，组合包
  卡片也画它，「整包 = 图钉 + 会话头」里的那枚图钉正是这一行。
- `opencode-header` 那行画自己的：新导出**属于这个地址**的一份 manifest
  `opencode-header.package.json`（`./opencode-header/package.json` 以前指向包根，
  现在指向它），由它声明 `icon: "./opencode-header.icon.svg"`。

图标本身是官方 OpenCode 标记：wordmark 的 `o` 字形（24×30，框厚 6），×0.8 居中放进
官方 36×36 viewBox —— 字形因此高 24 单位（框厚 4.8，内孔下方 9.6 见方的面板留在原
位），与 Host 自带 bundle 图标的光学尺寸同档（随手比过 asar 内
`@deepseek-ai/dsh-experimental-*` 的两枚：字形分别在 36 框里占到 24 与 18 单位高；
包根图钉是 18.4）。**魔改只有两处**：画布换成 36×36 的家族画布（官网那个 240×300
文件是竖长的），配色换成包根图钉那条蓝渐变、面板用同族浅蓝。

## 为什么必须各画各的（核实的读法）

`meta.icon` 由 DSH 画在组合包卡片与每一行上，`meta` 仍出自
`readPluginMeta(specifier, …)`，而 `specifier` 就是那一行的 `name`
（`@deepseek-ai/dsh-plugin-manager` 的 `listBundles()`：`packages?.metaOf(row.name, base)`；
本环境 asar 内 `/dsh/node_modules/@deepseek-ai/dsh-plugin-manager/lib/index.js`）。
链的末端是 `@deepseek-ai/dsh-app-boot` 的 `iconOf()`：

- 只认相对路径，绝对路径与任何带 scheme 的值一律拒绝；
- 只认 `.svg` / `.png` / `.jpg` / `.jpeg` / `.webp`，单个文件 ≤ 256 KiB；
- 文件必须在 manifest 所在目录之内（realpath 之后），内容再 base64 成 data URL
  交给前端（`dsh-client-ui-plugin-manager` 把它画成卡片/行上的那一格）。

地址相同就是同一份 manifest，图标也就只有一枚。两条行可以分别开关，却长得一模一样，
在列表里只能靠读标题分辨 —— 这就是要改的毛病。

## 排除的选项

- **在 `cordis.patch.yml` 的 insert 行里写 `icon`**：patch entry 没有这个字段，DSH
  也不读它，写了只会被当成未知键，图标照旧不出现。
- **把 data URL 写进 manifest**：`iconOf()` 拒收带 scheme 的值并报 metadata error，
  一行会带着错误标签出现，图标一样出不来。
- **两行各换一枚新图标（对称）**：`subagent-pin` 画图钉、卡片也画图钉，正是这一包
  想说的话；多一枚只换来一份要跟着维护的重复。
- **照抄官方原色**（亮底 `#656363`/`#CFCECD`，深底 `#B7B1B1`/`#4B4646`）：图标以
  data URL 进 `<img>`，一个文件要同时活在浅底与深底的卡片上，而官方两套各自只在一种
  底上成立 —— 亮底那套在深底只剩一块面板，深底那套在亮底几乎看不见。
- **自造一个无关标记**：复用官方几何让「这是 OpenCode 那一行」一眼可读；改动只限
  画布与配色，形状不是自由发挥的地方。

## 代价

两个新文件（`opencode-header.package.json`、`opencode-header.icon.svg`）加一条
`exports` 映射；`files` 要跟着长两条，否则打包产物里没有这枚图标，卡片静默退回默认
插画（`test/package.test.mjs` 与 `test/tarball.test.mjs` 都盯着这件事）。包根的
`icon.svg` 与组合包卡片**不动**。

守卫在 `test/patch.test.mjs`：逐行对着行地址的 manifest 断言图标能被 Host 画出来、
随包、且两条行不是同一个文件；规则本身唯一定义在 `test-support/manifest-icon.mjs`
（包根卡片与两条行走同一份），`test/package.test.mjs` 另带一组坏基线，证明读不出或
画不出的 `icon` 会被报出来而不是当没事。

视觉那一半只核对过一次，属于人工证据、和 `verify` 一样不进 `npm test`：用无头
Chromium 把候选画在浅底与深底卡片上，16 / 20 / 30 / 36px 各一档比对，确认小尺寸下
两行仍能一眼分开、且面板不会在任一底上糊掉。
