# 每行显示自己的名字

2026-09-28。Plugin Manager 里，组合包卡片与它的两条行各自显示什么名字。
本文只留决策本身、逐项核实过的位置、以及排除掉的选项；怎么挂载见
`README.md`「安装」，行名与 locale 的对应关系见 `AGENTS.md` 的仓库布局表。

## 结论

`cordis.patch.yml` 里每条 insert 行的 `name` 是**这一行自己的地址**：

- `id: subagent-pin` → `@edmund724/dsh-subagent-pin/subagent-pin`（导出 `plugin.js`）；
- `id: opencode-header` → `@edmund724/dsh-subagent-pin/opencode-header`（导出 `opencode-header.js`）。

每一行在 `locale/<行 id>/` 下有自己的一份 `en.json` / `zh.json`，并从**同一个**
地址再导出一份 `package.json`（当时两条行都指向包根的 `package.json`；会话头那行
后来换成自己的一份，只为它自己那枚图标，见
`2026-09-28-每行画自己的图标.md`）。
整包的标题与描述留在 `locale/en.json` / `locale/zh.json`，由卡片继续使用；
于是卡片是「子代理模型锁定 + OpenCode 会话头」，两条行分别只讲自己那一件事。

## 为什么必须分地址（核实的读法）

DSH 不读 patch 行里的任何显示字段。读法只有一条链，全在
`@deepseek-ai/dsh-app-boot` 的 `readPluginMeta()`（本环境 asar 内
`/dsh/node_modules/@deepseek-ai/dsh-app-boot/lib/index.js`）：

- 解析 `${specifier}/locale/en.json`，把**同一个真实目录**里的每个 `.json` 当成一种
  语言，再逐个用 `${specifier}/locale/<文件>` 解析一遍（`dictionariesOf()`）；
- 解析 `${specifier}/package.json`，字段缺失时用它回退（标题回退包名、描述回退
  `description`），图标也从它读；
- 两者都读不到就返回空 —— Plugin Manager 这时显示**模块 specifier** 本身。

调用侧的 `specifier` 就是该行的 `name`
（`@deepseek-ai/dsh-host-plugin-inventory` 的 `readPluginInventory()`：`metaOf(entry.options.name, base)`
与 `metaOf(row.moduleName, base)`）。合起来就是：**行名即地址，地址决定它显示的名字。**

现状因此有两个毛病，同一条链解释得通：

- 路由那行挂的是包根地址，与卡片共用同一份 locale：它的名字与描述都把会话头
  算成了自己的功能，而 `opencode-header` 那行可以单独关掉；
- 会话头那行是子路径、导出里没有它的 locale 与 `package.json`：它显示的是原始
  specifier，也没有图标。

## 排除的选项

- **只改包根的 locale 标题**：卡片标题会一起改（同一份 meta），而路由那行的描述里
  仍然写着会话头 —— 等于整包的卡片不再点名第二行、那一行却照旧替它签名。两头都不对。
- **给 patch 行加 `title` 字段**：DSH 没有这个字段，显示名一律按地址读，写了也不生效。
- **两行都挂包根**：地址相同就是同一份 meta，问题原样保留。
- **把行地址拆成两个文件**（例如新增 `subagent-pin.js`）：地址与实现是两件事，`plugin.js`
  本来就是路由那行的实现，多一个只做转发的入口文件没有换到任何东西。

## 代价

`exports` 多两类模式（`./<行>/package.json`、`./<行>/locale/*.json`），`files` 从
`locale/*.json` 放宽到 `locale/**`，`README.md` / `README-en.md` 的挂载示例行名与
`test/docs.test.mjs` 的行名表同步改。守卫在 `test/patch.test.mjs`：每行的地址必须
导出双语 locale 与 `package.json`（否则退回 specifier 或丢掉图标），且一行的标题与
描述不得复述另一行 —— 上面那两个毛病各有一条测试点名。

## 追加（同日）：这一行的 id 从 `opencode-session` 改为 `opencode-header`

行名是地址，也就是读者写在 profile 里的标识符，所以它得说清这一行是什么。它补的
是**一次请求上的一个头**，不是「一个会话」；旧名让人以为这一行保存或代表会话，而值
来自会话 id 这件事已经写在 `deriveSessionValue()` 与 `headerName` 上。`opencode-headers`
被否：`headerName` 是单数，这一行每次只写一个头。

跟着改名的是这一行自己的标识符：行 id、子路径 `./opencode-header`、`opencode-header.js`、
`locale/opencode-header/`、`docs/opencode-header.md`、`test/opencode-header.test.mjs`，
以及诊断前缀 `[opencode-header] ` 与 `Symbol.for('…/opencode-header/patch')`。
**不动的**有两类：网关要求的头名 `x-opencode-session`（不是我们的标识符），以及讲
值来源的名字（`headerName`、`sessionId`、`deriveSessionValue()`）与 README 里
「OpenCode Go 的会话头」这类功能名。

代价写在明面上：行 id 变了，profile 里若有人写过 `- id: opencode-session` 的覆盖或
禁用，那条会失配（本环境没有）；`Symbol.for` 的键也随之作废，所以同一进程里若新旧
两代同时挂着，两份包装各认自己的 key —— 正常路径是先卸载旧的再挂新的，不会同时存在。
