以及随之退役的独立包。本文只留决策本身、核实过的读法与排除掉的选项；怎么挂载见
`README.md`「安装」，行的显示名与图标为什么各走各的地址见

## 结论

- 新增第三行：`id: subagent-steer`、`name: dsh-subagent-pin/subagent-steer`，
  实现是 `subagent-steer.js`，由随包 patch 的一条 insert 挂载；
- 它按前两行同样的方式拥有自己的地址元数据：`subagent-steer.package.json`
  （含 `icon`）、`subagent-steer.icon.svg`、`locale/subagent-steer/{en,zh}.json`；
- 该行**不导出 `Config`**（它没有任何旋钮），于是 `cordis.patch.yml` 里它不带
  `config`，`Config.listConfigs` 对它报 `absent` 是正常状态，不是加载失败的信号；
- 独立包退役：`D:\DSH\dsh-subagent-steer` 目录删除，profile 的 `dependencies` 与
  `bundles` 两处去掉它，代码、测试与替身整体搬进本包。

## 为什么合成一个包

三行讲的是同一件事的三段：委派路由（谁跑哪个模型）、随请求走的会话标识、以及子代理
一旦存在之后怎么继续它。它们共享同一个运行时（Harness 自带的 Cordis）、同一组 Host
形状（`ctx.subagents`、tools 注册表、systemPrompt）与同一套验证纪律（`node:test` +
真实 Cordis 替身 + 文档守卫）。分成两个 bundle 的代价是把这套纪律连同文档双写一遍，
而两个 bundle 的启用状态又能各自漂移 —— 合并后一行一处真源，禁用/启用也不再有两个开关。

## 排除的选项

- **保留独立包，让本包的 patch 代插一行指向它**（`name: dsh-subagent-steer`）：行地址
  仍是另一个包，profile 里仍要装两份 bundle，双写与漂移一个不少；换来的只是不动文件位置。
- **跨包 re-export**（本包的 `exports` 把子路径指到另一个包的文件）：`exports` 只能指向
  包内文件；就算做得到，行地址与实际实现的归属也会分家。
- **并进本包但保留一个只做转发的入口文件**：多一个不承载语义的文件；「行地址与实现是
  两件事」这条结论在 `2026-09-28-每行显示自己的名字.md` 的排除项里已经否过一次。
- **给转向那行补一个空 `Config`**（`z.object({})`）：DSH 会因此给它一个 schema 状态与
  一张没有字段的表单，而这一行没有任何可写项；`absent` 才是诚实的答案。

## 代价

- `exports` 多三条映射、`files` 多三个包内文件与两个 `test-support/` 文件；
  `test/patch.test.mjs` 的行表、`test/docs.test.mjs` 的行名表、两份 README 与
  `docs/verification.md` 的逐文件计数都要跟着长（各自有守卫钉住自己那一面）。
- 包卡片与 `package.json` 的 `description` 变成三合一：标题变长是「一行一地址」这套
  设计的代价，换到的是每一行仍能单独开关、单独显示自己的名字与图标。
- 版本号 1.0.1 → 1.1.0（新增一行是功能变更）。独立包目录删除后，它的历史只留在它
  自己的仓库里；两份失传不了的理由（为什么存在、何时删掉）都已搬进本包 README 与
  本目录的另一份笔记。

## 装进 profile 的两处（本环境）

`~/.dsh/profiles/desktop/package.json`：删掉 `dsh-subagent-steer` 的 `link:` 依赖
与 `bundles` 里的同名条目；`dsh-subagent-pin` 的 `link:` 不动。重启 Harness 后，
第三行由本包的随包 patch 挂载（Host 插件按包名缓存模块，换代只有重启才生效）。
