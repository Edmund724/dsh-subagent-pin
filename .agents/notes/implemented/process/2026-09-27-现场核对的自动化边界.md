# 现场核对的自动化边界

## 这份笔记是什么

2026-09-27 架构评审的**候选 7**：「唯一的证据工具不可导入，验证是一张手工表」。笔记记下这次落地的边界 —— 哪些检查变成了可重跑的命令、哪些必须真人现场做、期望值从哪里来，以及为什么不做另外几种做法。

## 决定（2026-09-27）

1. **把表拆成两半。** 生产证据（跑一次真 Harness 操作）无法自动化；「读日志下判断」这一半变成一条命令：`npm run verify -- --lead <lead 会话日志>`。
2. **期望值来自那次运行自己。** 优先级：`--expect` > `--default-model`（并校验它属于该运行冻结的清单，与插件的 `defaultModel` 规则同构）> 该运行 `subagent/model-selection-policy` 里 `allowedModels` 的第一项。**不读活 Settings** —— 验的是「那一次」，不是「现在」。
3. **证据落在 child 自己的日志里。** one-shot 与 continuable 都用 child 的 `request/header`（`data.header.config`）；continuable 另外断言 `subagent/descriptor` 的 `agentProvider`/`agentModel`（one-shot 的 descriptor 根本没有路由字段，`descriptor.js` 的类型定义如此），以及 descriptor 与 header 互相一致。child 日志由 lead 的 `subagent/catalog` 的 `childId` 定位为兄弟目录；`--child` 指向别处的日志。
4. **打包卫生。** `scripts.test` = `node --test "test/*.test.mjs"`（显式 glob，不依赖 Node 默认 glob；测试文件一律叫 `test/*.test.mjs`，helper 放 `test-support/`）；`scripts.verify`；`engines.node = ">=22.15"`（两个工具都要 zstd，测试用 `zstdCompressSync` 造帧）；`exports` 加具名 `./verify`。
5. **CLI 只做两件修正。** `read-session.mjs` 的第二个参数改为**完整 type** 匹配；打印**整条**事件，不再截断。

## 为什么：候选 7 的三条指控，逐条实证

- **工具随包发布却不可导入。** `files` 的 `tools/*.mjs` 让它进 tarball，而 `exports` 只有 `.`/`./package.json`/`./locale/*.json`。把 tgz 解到临时目录模拟安装后，`import '@local/dsh-subagent-pin/tools/read-session.mjs'` 报 `ERR_PACKAGE_PATH_NOT_EXPORTED`。开发期看不出来，因为本机 profile 的 `node_modules/@local/dsh-subagent-pin` 是指向仓库的符号链接，导入从不经过 export map。
- **README 教的操作会产生非法 JSON。** CLI 的 `JSON.stringify(event).slice(0, 1200)` 把 `request/header`（真实长度 24k–31k，全部超过 1200）截成不可解析的片段；`request` 过滤器是子串匹配，实测一条命令返回 `request/header` + `request/context` + `session/title-llm-request` 三种 type。
- **唯一的证据工具没有任何消费者与测试。** 全仓库对 `read-session` 的引用只在 README 与工具自身；测试目录没有 import 过它，帧切分、过滤、打印三件事都没有断言保护。
- 另外两处清单缺口：没有 `scripts`（README 让用户手敲 `node --test`，靠默认 glob）与没有 `engines`（两个 Node 下限只写在散文里）。

## 已考虑并否决

- **让 `verify` 读活 profile / Settings 来推期望值。** 会让「现在」污染「那一次」：被验的运行当时冻结的是哪份清单，只有它自己的日志知道（`subagent/model-selection-policy`）。
- **把 `read-session.mjs` 也加进 `exports`。** 它是 `verify` 的实现细节；公开面只给一个具名入口，比通配 `./tools/*` 更小也更好守（`test/package.test.mjs` 钉住 `exports` ⊆ `files`）。
- **把 README 的表格变成 `verify` 的 manifest。** 文档里放机器标记正是 `test/docs.test.mjs` 的注释解释过的反模式：检查器只能证明标记被维护，不能证明话是真的。表格留给读者，`verify` 的支撑面是日志。
- **给 CLI 加 `--truncate` 之类的开关。** 截断是给终端读者的方便，却让输出不可解析；需要时管道给 `head`/`Select-Object -First` 即可。
- **`scripts.test` 指向目录（`node --test test/`）。** 实测 Node 25 把它当成模块路径并报 `MODULE_NOT_FOUND`；`node --test "test/*.test.mjs"` 由 Node 自己展开 glob，pwsh 与 cmd 下都成立。

## 边界（写下来免得下次再推一遍）

- **不可自动化的部分**：制造证据（真跑 Harness），以及「禁用 = 不改变」（要改 profile 组合）、投影契约里的 `status`（只有活 Host 看得到）。这些行在表里 `verify` 列写 `—`。
- **可自动化的部分**：默认项、显式路由、`defaultModel`、continuable descriptor、Lead 不受影响 —— 只要那次运行留下了日志。

## 实测

- 借本机真实日志跑过：24 份 lead 日志里 3 份通过、2 份失败（child 落在继承来的父路由上，正是这张表要抓的形态）、其余没有 child。
- 候选 5 那次运行（4 个 continuable child）：13/13 通过。

## 测试

`test/read-session.test.mjs`（5 项，自己造多帧/坏尾帧日志）、`test/verify-session.test.mjs`（9 项，自己造一次运行的两份日志，含 child 日志缺失、descriptor 与 header 不一致、期望值越出冻结清单）、`test/package.test.mjs`（3 项，`exports` 与 `files` 的一致性）。
